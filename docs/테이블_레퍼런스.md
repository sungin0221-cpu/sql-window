# 테이블 레퍼런스 — 통신사 가상 데이터 12표

- 기준일: 2026-11-19 · `data/*.parquet` 12개를 `edata9-data` 도구(읽기 전용 DuckDB)로 센 값
- 숫자는 모두 실제로 센 것이다. 원인이나 뜻은 짐작하지 않고 «확인 안 된 것»에 적었다
- 이름·의견·내용 같은 문장 열은 값을 읽지 않고 빈 값 수와 고유 수만 셌다
- 각 표의 맨 아래에 센 SQL이 있다. 창의 «직접 묻기»에 붙여 다시 셀 수 있다

## 표를 잇는 법

«고아»는 상대 표에 없는 값의 건수다. «불어남»은 왼쪽 표에서 오른쪽 표를 붙일 때 줄이 늘어나는지를 뜻한다.

| 왼쪽 열 | → 오른쪽 열 | 고아 | 불어남 |
|---|---|---:|---|
| usage_monthly.customer_id | customers.customer_id | 0 | customers에서 붙이면 고객당 1~12줄. 이용 기록이 없는 고객 15명 |
| support_tickets.customer_id | customers.customer_id | 0 | customers에서 붙이면 고객당 여러 줄 (고객 23,398명 · 문의 32,789건) |
| support_tickets.agent_id | agents.agent_id | 0 | 상담원당 130~446건 |
| csat_survey.ticket_id | support_tickets.ticket_id | 0 | 안 불어남 (문의당 설문 0~1건, 설문 없는 문의 23,102건) |
| csat_survey.customer_id | customers.customer_id | 0 | 같은 ticket_id의 문의 고객과 다른 건 0 |
| voc.customer_id | customers.customer_id | 0 | 고객당 1~4건 |
| voc ↔ support_tickets | (ticket_id 없음) | — | **고객으로만 이을 수 있고, 양쪽이 다 불어난다(N:M)**. VOC 고객 7,124명 중 3,527명은 문의가 없다 |
| customers.visitor_id | sessions · funnel_events.visitor_id | 0 | 1:N. visitor_id가 있는 고객은 6,485명뿐이다 |
| customers.campaign_id | campaigns.campaign_id | 0 | 캠페인당 고객 29~92명. 빈 값 43,515 |
| sessions.campaign_id | campaigns.campaign_id | 0 | 빈 값 111,948 |
| funnel_events.session_id | sessions.session_id | 0 | 세션당 최대 6줄. 퍼널 기록이 없는 세션 105,795 |
| ad_spend.campaign_id | campaigns.campaign_id | 0 | 캠페인당 2~91줄 |
| experiment_assignments.experiment_id | experiments.experiment_id | 0 | 실험당 29,363~90,552줄 |
| experiment_assignments.visitor_id | sessions · funnel_events.visitor_id | 0 | 1:N |
| experiment_assignments.visitor_id | customers.visitor_id | — | 고객과 맞는 줄 9,375 (6,063명). 나머지는 고객이 아닌 방문자 |

## 먼저 알아 둘 것

1. **customers × usage_monthly를 그대로 붙이면 523,825줄이 된다.** 사람을 셀 때는 `COUNT(DISTINCT customer_id)`를 쓴다. 이용 기록이 없는 고객 15명은 INNER JOIN에서 조용히 빠진다.
2. **csat_survey에는 2026년 설문이 52건 있다.** 2025년만 볼 때 넣을지 정해야 한다.
3. **experiments의 start_date · end_date는 날짜가 아니라 글(VARCHAR)이다.** 비교하려면 CAST해야 한다. 5행 모두 바뀐다.
4. **usage_monthly.is_active는 모든 줄이 참이다.** 이 열로는 활성 고객과 비활성 고객을 나눌 수 없다.
5. **voc.voc_category(6종)와 support_tickets.ticket_category(5종)는 분류 체계가 다르다.** 해지는 «해지관련»과 «해지»로 이름도 다르다.
6. **funnel_events는 같은 세션 안에서 단계 순서와 시각 순서가 어긋난다.** 다음 단계가 앞 단계보다 이른 쌍이 112,784쌍 가운데 56,246쌍이다. 순서는 `step_order`로 본다.
7. **sessions의 campaign_id가 있는 줄 182,116줄 가운데 156,363줄은 날짜가 그 캠페인 기간 밖이다.**
8. **campaigns.total_budget과 ad_spend.spend 합계는 캠페인마다 1~48원 다르다.** 120개 모두 그렇다.

- visitor_id와 campaign_id는 같은 43,515줄에서 비어 있다. 값이 있는 6,485줄은 acquisition_channel이 campaigns와 모두 일치한다.
- 요금제와 월 요금은 1:1로 짝지어진다. 알뜰 19,000 · LTE기본 33,000 · LTE무제한 45,000 · 5G스탠다드 55,000 · 5G프리미엄 89,000원이다.
- 해지 여부와 해지 날짜는 서로 맞는다. 해지인데 날짜가 없는 줄, 유지인데 날짜가 있는 줄, 해지일이 가입일보다 앞선 줄 모두 0이다.
- 가입은 2018년부터 있지만 해지 날짜는 2025년에만 있다.
- 가입일이 퍼널 «첫결제» 날짜와 같은 고객은 6,485명 중 6,459명, «개통» 날짜와 같은 고객은 6,450명이다.

**확인 안 된 것**
- visitor_id · campaign_id가 빈 43,515명이 온라인 퍼널 밖에서 가입한 고객인지
- 2025년 이전 해지 고객이 표에서 빠진 것인지
- usage_monthly에 없는 15명의 사정
- region 분포

## usage_monthly

한 줄 = 고객 × 월 · 행 수 523,825 · 기간 2025-01 ~ 2025-12 · 키: customer_id + year_month (행 523,825 / 고유 523,825)

| 열 | 형식 | 빈 값 | 값 종류 | 값 / 범위 (최소 · 중앙 · 최대) |
|---|---|---:|---:|---|
| customer_id | VARCHAR | 0 | 49,985 | 잇는 열 |
| year_month | VARCHAR | 0 | 12 | 2025-01 ~ 2025-12. 월별 43,845줄(1월)에서 43,412줄(12월)로 줄어든다 |
| data_gb | DOUBLE | 0 | 7,628 | 0.23 · 14.36 · 128.27 |
| voice_min | BIGINT | 0 | 180 | 55 · 134 · 239 |
| sms_count | BIGINT | 0 | 33 | 0 · 12 · 32 |

| is_active | BOOLEAN | 0 | 1 | **모든 줄이 참** (523,825) |

**눈여겨볼 것**
- 12개월이 다 있는 고객은 37,630명이다. 1~11개월만 있는 고객은 개월 수마다 918~1,248명이다.
- 첫 달과 마지막 달 사이에 빠진 달이 있는 고객은 0명이다.
- 가입월보다 앞선 줄과 해지월보다 뒤인 줄은 모두 0이다.
- billing_amount가 customers.monthly_fee보다 작은 줄이 465,995줄(약 89.0%)이다.

**확인 안 된 것**
- billing_amount와 monthly_fee가 어떤 관계인지 (할인이나 일할 계산 여부)
- is_active가 항상 참인 이유 (이용하지 않은 달이 아예 빠진 것인지)
- 월별 줄 수가 줄어드는 이유

```sql
WITH u AS (SELECT u.*, c.signup_date, c.churn_date, c.monthly_fee, CAST(u.year_month||'-01' AS DATE) m
           FROM usage_monthly u JOIN customers c USING(customer_id))
SELECT
 SUM(CASE WHEN m < date_trunc('month', signup_date) THEN 1 ELSE 0 END) before_signup_month,
 SUM(CASE WHEN churn_date IS NOT NULL AND m > date_trunc('month', churn_date) THEN 1 ELSE 0 END) after_churn_month,
 SUM(CASE WHEN billing_amount < monthly_fee THEN 1 ELSE 0 END) bill_below_fee
FROM u
```

## sessions

한 줄 = 방문 세션 1회 · 행 수 294,064 · 기간 2025-01-01 ~ 12-31 · 키: session_id (행 294,064 / 고유 294,064)

| acquisition_channel | VARCHAR | 0 | 5 | 검색 34.2 · 디스플레이 23.9 · 제휴 19.9 · 추천 14.0 · 오프라인 8.1% |

**눈여겨볼 것**

- 캠페인 기간 밖 세션 156,363줄이 무엇을 뜻하는지
- duration_sec가 0인 29줄의 성격
- 퍼널 기록이 없는 105,795세션이 재방문 세션인지

## funnel_events

|---|---|---:|---:|---|

| visitor_id | VARCHAR | 0 | 180,000 | 잇는 열 |
| session_id | VARCHAR | 0 | 188,269 | 잇는 열 |
| event_timestamp | TIMESTAMP | 0 | 232,703 | 2025-01-01 01:29:30 ~ 2025-12-31 23:59:59 |
| event_date | DATE | 0 | 365 | event_timestamp의 날짜와 다른 줄 0 |

| step_order | funnel_step | 줄 수 |
|---:|---|---:|
| 1 | 랜딩방문 | 180,000 |
| 2 | 요금제조회 | 81,164 |
| 3 | 신청시작 | 18,989 |
| 4 | 신청완료 | 7,686 |
| 5 | 개통 | 6,729 |

**눈여겨볼 것**
- 방문자마다 같은 단계가 두 번 나오거나 중간 단계를 건너뛴 경우는 0명이다.
- 단계가 여러 세션에 나뉜 방문자는 7,186명이다. 세션 단위로 보면 단계가 빠진 세션이 8,269개다.
- **같은 세션 안에서 다음 단계가 앞 단계보다 이른 쌍이 56,246쌍이다.** 전체 112,784쌍 가운데다.
- event_date가 세션 날짜와 다른 줄이 94줄 있고, 모두 하루 뒤다.
- 첫결제에 이른 방문자 6,485명은 모두 customers에 있고, customers의 visitor_id 6,485개와 서로 정확히 맞는다.

**확인 안 된 것**
- 단계 순서와 시각 순서가 어긋나는 이유
- 하루 뒤인 94줄이 자정을 넘긴 세션인지
